# App Flow Document

## Onboarding and Sign-In/Sign-Up

When a new visitor arrives, they land on the public home page at the project root. From there, they can choose to jump straight into the IDE in a temporary guest session by clicking the "Start Coding" button or they can sign up for an account to save projects and access advanced features. If they decide to register, they are taken to the Sign Up page, where they can enter an email address and password or choose to authenticate with a linked GitHub account. After submitting their details, they receive a confirmation email. Once confirmed, the user is automatically signed in and redirected to the main dashboard. Returning users can click the Sign In link on the home page to enter their email and password or use the GitHub button to log in. A Forgot Password link is provided on the Sign In page, sending a reset link by email when clicked. Signing out is as simple as selecting the Log Out option from the user menu in the header, which clears the session and returns the visitor to the public home page.

## Main Dashboard or Home Page

Upon signing in or starting as a guest, the user lands on the dashboard, which is divided into three main panels. On the left, the file explorer lists all project files and folders in a collapsible tree view. In the center, the chat interface displays conversation history with the AI assistant and provides an input box for new commands. On the right, the live preview pane shows a real-time rendering of the project’s current state in an embedded iframe. A top navigation bar contains the project name, a button to create a new file, and a user menu with links to Settings and Log Out. The layout is responsive, so on smaller screens the panels stack vertically, with tabs to switch between Explorer, Chat, and Preview views.

## Detailed Feature Flows and Page Transitions

When a user types a command in the chat input, such as "Create a Header component," the message is sent to the `/api/agent` endpoint. The dashboard enters a loading state while the AI orchestrator in the backend decides which tools to use. Once the orchestrator instructs the `edit_file` tool, the file explorer updates to show the new file. The code editor opens that file in place of the chat input, allowing the user to view or edit its contents. Saving changes triggers a hot reload in the development server inside the sandboxed container, and the preview pane automatically reflects the update. If the user clicks on any file name in the explorer, the editor view replaces the chat to show the file contents. To return to the chat, they click the Chat tab in the top of the central panel. 

If the user decides to rename or delete a file, they right-click its name in the explorer and choose the appropriate action. The frontend confirms the selection in a modal, then calls an API route that uses the `bash` or `fileSystem` tool to modify the project in the container. After the operation completes, the explorer and preview pane refresh. For longer commands or streaming outputs, such as running tests or building the project, the chat area and a built-in terminal tab show incremental results via WebSockets, letting the user follow progress in real time.

## Settings and Account Management

Users access account settings by clicking their avatar in the header and choosing Settings. On the Settings page, they can update their display name, email, and password. A separate tab allows them to connect or disconnect their GitHub account for project import and export. If the user has API keys stored for third-party services, they manage these under the Integrations section. All changes are saved with a click of the Save button, triggering an API call to update their profile in the database. From Settings, a back arrow returns the user to the dashboard, preserving any open files or chat history.

## Error States and Alternate Paths

If a user enters a command the AI cannot understand, the chat displays a polite error message suggesting rephrasing. When a file operation fails because of a typo in the path or a permissions error, a red notification banner appears above the editor explaining the issue. In the event of network loss, the app shows a full-screen message with a Retry button, pausing any ongoing chat or container actions. Should a sandboxed container crash or time out, the dashboard indicates that the workspace needs to restart and offers a Reload Workspace button. Clicking it spawns a fresh container and reloads the project directory. If a logged-in user tries to access a premium feature they don’t have permission for, the app seamlessly guides them to a billing page where they can upgrade their subscription before returning to the requested flow.

## Conclusion and Overall App Journey

From the moment a visitor lands on the public home page, they can immediately begin experimenting in a guest session or create an account to unlock project saving and integrations. Once on the dashboard, the user interacts with an AI assistant in the chat panel to generate or modify code, navigates files in the explorer, and watches live updates in the preview pane. They manage their profile and connected services in Settings and see clear feedback whenever something goes wrong, with paths to recover or retry. Throughout each session, the app maintains a smooth, connected flow so that creating components, editing code, and previewing results happen in a continuous, intuitive cycle.
